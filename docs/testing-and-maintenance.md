# 验收与维护

## 分开记录三类验证

1. **静态检查**：结构、元数据、相对链接、交付内容与安装冲突处理。
2. **模拟场景**：给独立 agent 页面事实，让其判断下一步与完成状态。此类验证不执行网页。
3. **租户验收**：在指定环境实际完成操作，记录对象、版本、运行实例和目标用户结果。

本次实际执行范围见 [验证报告](validation-report.md)。前两类通过不能替代第三类。

## 本地检查

```sh
python3 scripts/suite.py validate
python3 -m unittest discover -s tests -v
python3 scripts/suite.py package --output dist
```

`suite.py validate` 检查套件布局、必要元数据和本地文件链接，不是完整 YAML 解析器，也不会验证官网可用性。交付时另使用 skill-creator 的 `quick_validate.py` 验证每个 skill 的 YAML 与基本格式。

## 真实租户试点

先建立一个小型、可清理的开发/测试范围。记录使用的浏览器工具、界面语言、环境类型和 agent 框架。不要在生产数据上运行以下用例。

| 用例 | 操作 | 必须记录的证据 |
|---|---|---|
| 环境定位 | 只读进入指定产品和对象 | 租户、环境 ID、对象链接 |
| agent 草稿 | 创建或编辑，保存，测试一条对话 | 重开后的字段、测试结果、未发布状态 |
| 知识源 | 加一份授权测试资料并提问 | Ready、引用与资料内/外回答 |
| flow 集成 | 发布 DEV flow，再从 agent 调用 | 参数、同一次运行、返回值、实际结果 |
| Canvas 应用 | 连接测试数据，保存/发布/共享试点组 | Live 版本、用户权限、数据访问 |
| Model-driven 应用 | 添加测试表页面并验证角色 | 页面、表单/视图、目标用户可见数据 |
| Solution 部署 | DEV → TEST 导入或管道 | 包版本、导入历史、连接变量、目标渠道验证 |
| 中断恢复 | 模拟提交后页面断开 | 重连后查到已有结果，未重复创建/运行 |

涉及写入、通知、角色或发布时，先把用例的实际影响纳入试点授权。已有明确授权不用逐步重复确认。

若任务只允许草稿，跳过需要发布才能运行的 flow 用例，并记录“未执行”。若没有目标用户身份，不能把 maker 测试结果当作用户访问验收。

## 失败记录

记录用户原请求、读取的 skill、页面事实、实际动作、错误、期望差异及已发生副作用。用 [交付记录](../skills/power-platform-web/assets/delivery-record.md) 保留必要证据。不要存储认证截图、token 或完整敏感对话。

根据失败修改最小规则。不要为一次异常新增覆盖所有任务的审批或检查清单。回归测试应针对实际失败及受影响邻近流程。

## 维护触发

发现以下变化时复查对应官方原页：新/旧体验切换、菜单消失、发布状态变化、输入输出限制变化、连接认证变化、渠道或许可限制变化。对近期变动且与当前操作相关的步骤，执行前也应重新核查。

更新来源核查日期、支持范围及验证记录。安装结构或共用引用变更时，重新执行本地检查与打包。维护频率由使用频率和实测故障确定；本项目没有创建自动监控任务。
