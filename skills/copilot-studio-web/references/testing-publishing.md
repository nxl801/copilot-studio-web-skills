# 标准框架：测试、发布与排障

核验日期：2026-10-22。新框架的 Preview 与发布状态见[体验识别](experience-detection.md)。发布治理与跨环境交付使用 [power-platform-release](../../power-platform-release/SKILL.md)。

## 草稿测试

1. 保存当前修改，处理 Topic checker 的实际错误。
2. 选择顶部 Test，打开 Test your agent。
3. 从新测试会话开始运行用例。修改主题不会自动清空旧会话。
4. 对生成式编排查看 activity map 中的组件选择与调用；需要逐节点定位时使用 Track between topics。
5. 记录输入、预期结果、实际结果与可见证据。只保留必要的诊断信息。

上述入口依据[官方测试说明](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-test-bot)。以下用例是本套件的交付建议，不是微软规定的固定测试数量。

| 改动类型 | 至少覆盖的行为 | 合格证据 |
| --- | --- | --- |
| 知识与指令 | 资料内问题、资料外问题、相关多轮追问 | 答案符合任务与资料范围，引用可核对 |
| 主题 | 正常分支、缺少输入、其他条件分支 | 正确节点运行，必需信息已收集，跳转能结束 |
| 工具 / 流程 | 正常输入、无结果或错误、权限边界 | 参数和身份正确；实际系统结果与 agent 回复一致 |
| 认证 | 目标身份能访问，非目标身份按设计受限 | 目标渠道的认证表现正确；不能仅使用 maker 身份判定 |

测试有写数据、发信、审批或触发外部工作时，先使用任务已指定的测试对象和范围。没有相应授权时，完成配置与只读验证，把未运行的动作清楚列出。不要对真实业务记录做“试一下”。

## 发布与渠道验证

发布到 Teams 试点用户或组时，另读 [Teams 试点发布](teams-pilot.md)，区分聊天权限、商店可发现性和团队频道/群聊。

发布前准备好当前环境、agent 链接、变更内容、测试结果和目标渠道。检查该 agent 已连接的其他渠道；一次发布可能更新所有已连接渠道。若授权已覆盖目标与影响范围，继续执行，不重复申请同一许可。

| 阶段 | UI 锚点 / 操作 | 完成证据 | 出错处理 |
| --- | --- | --- | --- |
| 发布当前版本 | agent 顶部 Publish → 阅读摘要 → Publish 确认 | 明确成功状态；记录显示的时间或版本 | 保留错误及相关组件；没有结果时先回读状态，避免重复发布 |
| 配置渠道 | Channels → 用户指定渠道 → 按当前页面引导配置 | 渠道显示已配置，并取得实际访问入口 | 若禁用，检查组织策略、认证与渠道条件；不改成公开渠道绕过 |
| 分发访问 | 依据任务使用已授权的安装、共享或管理员分发方式 | 目标用户能找到或打开 agent | “已发布”不等于已授予用户访问 |
| 端到端验证 | 在真实目标渠道开启新会话，执行代表性用例 | 新版本行为、认证、工具输出均符合预期 | 区分发布传播、会话缓存与实际配置错误 |

对持久会话，可用渠道支持的 `start over` 开启新会话。不要因旧会话仍显示旧内容就反复发布。Demo website 用于团队试用，不作为生产渠道交付。它也不能替代带用户认证工具的目标渠道测试。[发布与渠道官方说明](https://learn.microsoft.com/en-us/microsoft-copilot-studio/publication-fundamentals-publish-channels)

“发布成功”是平台状态；“部署验证完成”还需要目标渠道证据。如果任务止于草稿，交付状态写为“已保存，未发布”。如果缺少真实用户身份，只能报告 maker 身份验证结果及未验证范围。

## 定位失败

按最窄范围定位：当前页面错误 → 对应组件 → 连接或权限 → 环境策略。一次只改变与证据有关的配置。复测通过后结束，不扩大测试到无关系统。

| 现象 / 错误 | 检查与处理 |
| --- | --- |
| 知识未就绪或没有答案 | 使用[知识状态表](authoring.md)；先核对来源范围与身份 |
| 工具未触发或选错工具 | 查看编排设置、工具说明、输入定义和实际调用记录；不要同时重写所有指令 |
| 流程不在添加列表 | 核对环境、Solution、触发器、响应动作和发布状态；Power Automate cloud flow 不一定出现在 Copilot Studio Flows 列表 |
| `BindingKeyNotFoundError` | 检查流程参数是否增删改名；记录原映射后更新或重新添加该流程引用，再验证输入 |
| `FlowActionBadRequest` | 比较变量实际类型与流程参数类型 |
| `FlowActionException` | 查流程运行和输出 schema；确认每条响应分支返回要求的字段 |
| `FlowActionTimedOut` | 查运行耗时与响应位置；按[同步/异步分支](authoring.md)选择适用处理，不能盲目增加重试 |
| 认证失败 / `FlowMakerConnectionBlocked` | 检查目标身份、连接和租户策略；需要管理员或连接所有者处理时保留具体请求 |
| 发布失败 | 读取发布详情和 checker；核对渠道、认证、数据策略及依赖组件 |
| 页面操作结果不明确 | 按共享浏览器约定回读当前对象状态；不要通过重复创建、提交或删除来试探 |

错误代码依据[微软排障文档](https://learn.microsoft.com/en-us/troubleshoot/power-platform/copilot-studio/authoring/error-codes)。保持代码原文，错误中的敏感数据只在用户批准的存储位置留存。
